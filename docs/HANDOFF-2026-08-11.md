## The model (migration 0030)

**Settled history folds, open items survive.** A pre-cutover row is deleted only if
fully settled; where a khata slot exists (vendor / labour / account) both settled and
open history fold into it because settlement there is party-level. Buyers fold
nothing — settlement is row-level, so unsettled sales survive as rows.

- `go_live_preview(farm, cutover)` — read-only plan, powers the wizard.
- `go_live_convert(farm, cutover)` — single transaction: archive → fold → delete →
  re-verify every displayed balance → abort on any mismatch. One shot (refuses if
  `go_live_date` set). Cutover must be the 1st of a month (monthly salary caps).
- Stock opening = **stored `current_stock` minus surviving post-cutover rows**, not the
  pre-cutover derived sum — an old client clamped negative stock to zero, and the
  displayed figure is the invariant. This is why the first two live runs aborted
  (plus: `total_cost` is GENERATED on both inventory tables; count-log `reason` is
  NOT NULL). Repo 0030 carries all fixes; 0030a is a parity stub.
- `v_expense_ledger` capital branch now excludes pre-go-live small equipment.
